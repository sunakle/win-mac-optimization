# DeepSeek в Docker

Это чистая установка DeepSeek Harness с рабочей папкой и сетевым фильтром. Она не переносит личные чаты, ключи и сторонние плагины. GPT4chan в контейнер не подключается.

1. Установите Docker Desktop и завершите первый запуск WSL.
2. Проверьте `docker info`.
3. В PowerShell выполните `.\deepseek\Setup.ps1 -Apply` из корня репозитория.
4. После сборки откроется локальная страница. Войдите в DeepSeek и выберите модель в настройках.

По умолчанию файлы находятся в `%LOCALAPPDATA%\WinMacRestore\DeepSeekBox`, проекты — в папке `workspace` внутри неё. Можно выбрать другой диск: `.\deepseek\Setup.ps1 -Apply -Root 'G:\Ai\DeepSeekBox'`.

Для следующих запусков: `.\deepseek\Start.ps1 -Root 'G:\Ai\DeepSeekBox'`. Для остановки: `.\deepseek\Stop.ps1 -Root 'G:\Ai\DeepSeekBox'`. `Stop.ps1` сохраняет том с чатами. Не запускайте `docker compose down -v`, если чаты нужны.

В `allowed-domains.txt` перечислены разрешённые домены. Если выбрана сторонняя модель, добавьте её домен **после проверки адреса**, затем пересоберите только прокси: `docker compose -f '<Root>\compose.yaml' build egress-proxy` и `docker compose -f '<Root>\compose.yaml' up -d`. Ключ API храните в настройках DSH, не в этом репозитории.

Контейнер видит только свою папку `workspace` и собственный том. Не кладите в workspace личные секреты и исходный проект без резервной копии. Окно доступно только с этого компьютера на `127.0.0.1:3080`.

Первый запуск может занимать несколько минут: `Start.ps1` ждёт до 15 минут и показывает статус. Если не запустилось, проверьте `docker compose -f '<Root>\compose.yaml' ps` и журнал контейнера локально; не публикуйте строку входа с `?token=`.
